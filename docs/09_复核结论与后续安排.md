# 松鼠备份复核结论与后续安排

本轮从课程资料和SquirrelBackup0.1.0发布包开始复核，形成0.2.0工作版本。原包及0.1.1发布仍保留用于追溯；新版以docs/03_软件测试报告.md和test-results中的实际结果为准。

## 1 原有基础与本轮改进

原版已有C++核心、原生GUI、CLI、自定义归档、Huffman、系统密码库封装、定时和变化检测。改动前的72项测试在本轮复跑通过，记录保存在baseline-0.1.0.log。0.1.1的82项用例属于此前修订；0.2.0为97项命名用例，GUI内部53项断言另计。

| 发现的问题 | 处理方法 | 对应检查 |
| --- | --- | --- |
| 只读根目录恢复失败，失败暂存不易清理 | 构建暂存时保留必要权限，发布后恢复根权限；清理不跟随外部链接 | 只读恢复与异常清理回归 |
| 等尺寸改写后恢复mtime可能漏检 | 扫描与变化指纹加入纳秒ctime；读前读后检查文件状态 | 保留mtime改写和源变化测试 |
| 自动任务错误参数进入反复重试 | 启动前验证源类型、参数适用范围和完整整数输入 | CLI及GUI参数测试 |
| 单次操作和当前快照无法取消 | Operation贯穿扫描、块处理、元数据和发布；取消清理未完成输出 | 备份、恢复各5阶段取消与任务停止 |
| 打包后目录又变化仍发布 | 封装后重新扫描并比较选定源树，不比较读取影响的atime | 新增、删除、改元数据回归 |
| 界面缺少进度，忙碌时可修改输入 | 显示阶段、当前路径和进度，禁用相关输入；常见日志中文化 | AppKit内部状态与真实运行截图 |
| 关闭、退出与停止时机不清楚 | 请求取消，清理结束后完成关闭或退出 | 代理方法断言；实际窗口操作待人工 |
| 资料版本不一致 | 统一程序、设计、报告、UML、PPT、讲稿和视频 | 版本检查、渲染检查与最终包复核 |

当前代码还通过-Wall -Wextra -Wpedantic -Werror编译、cpplint检查与Sanitizer复测。Huffman随机输入测试单列次数，不计入97项。长期测试实际状态、性能测量和兼容组合见03报告，避免多份文件中的时间采样互相冲突。

## 2 对截图建议的调整

程序先修订并验证，再按真实接口整理模型和报告。现有7张UML图已保存为可编辑StarUML模型，官方7.1.1 CLI成功读取并导出，结构检查为1066个唯一标识、0个悬空引用。报告插图由项目模型直接渲染，官方试用导出的水印原图完整保留在docs/uml/staruml-export。三人仍需熟悉模型，能够解释关系与流程。

Word报告已经套入课程原模板，保留封面、页面设置和表格结构；另有PDF和Markdown。9页PPT已填组号、姓名学号、算法依赖、测试、均衡主责和有日期的计划。115秒实际应用后台演示已生成，并完成全片解码及关键画面检查。它不是人工鼠标验收，系统选择器仍需单独操作。

不继续堆叠网络或增量等新功能。当前重点是正确性、取消反馈、资料一致性，以及三人能实际复现和讲清楚已有实现。

## 5 验证的实际范围

发布前复查不是多文件原子快照，协作取消不承诺固定时限，轮询不能捕获两次采样之间短暂出现的变化。应用不提供网络、增量、ACL、设备节点或完整macOS元数据；不同属主恢复可能产生权限警告。故障注入与实际SIGKILL已有专项补测，范围见03报告；系统选择器、跨机器、外置卷、真实磁盘耗尽、掉电及未列出的终止时机仍未验证。

源码检查最后只修改了头文件包含、等价类型转换与长字符串排版；重建前后Mach-O各文件映射节内容一致，记录见lint-rebuild-comparison.json。长期测试继续使用原冻结二进制，完整哈希单独保存；不把签名、调试信息和完整文件哈希的差异隐去。
