## 版本管理

先检查 git log 和 git status。建议每个可运行阶段单独提交，稳定演示版本使用标签。若小组协作，可从 main 创建 feat/模块名 分支，完成构建和测试后再合并，不直接在未验证版本上录屏。课程报告里的成员分工与贡献应按真实情况填写。

本人创建好私有在线仓库后，可在终端将其地址设为 origin 并推送 main。不要把密码、API Key、真实个人备份或 .tools 依赖虚拟环境加入远程仓库。课程原始材料和 demo 运行数据已被 .gitignore 排除；源码包附带测试框架和许可证，可供离线重建。

发布包如包含 source-history.bundle，可以用 git clone source-history.bundle 新目录 恢复项目本地历史。这不是在线仓库的替代，也不表示已上传课程平台。

## 可复现验证顺序

1. make all 构建 CLI 和原生应用。
2. make test 运行单元、集成和异常归档测试。
3. make sanitize 运行 AddressSanitizer 与 UndefinedBehaviorSanitizer。
4. make lint 使用项目约定检查代码；make fuzz 运行 60 秒种子变异与随机输入测试。
5. python3 tests/benchmark.py build/squirrel 记录性能；python3 tests/stability.py build/squirrel 600 运行十分钟反复修改与自动快照测试。
6. 在图形登录会话运行应用内部 --self-test，使用全新的测试目录；文件选择器和真实点击仍需人工验收。
7. 将当前0.1.1测试结果写入03_软件测试报告.md，再运行 python3 scripts/write_report.py 生成05综合报告；随后统一生成HTML/PDF、检查内容和版面，再执行 make package。原72/72仅是0.1.0基线；不能修改代码后仍把旧数字标成本轮结果。
8. 发布包重新解压并独立构建/测试，检查版本、部署目标、程序启动与SHA256清单；旧0.1.0 PPT/PDF仅作历史参考，最终展示前更新。
