# 开发与提交检查

当前版本0.2.0。本地Git记录保留原版和本轮改动，公开仓库为https://github.com/Peregrinate-PG/SquirrelBackup。第2讲要求GitHub/Gitee在线版本库；Teambition或类似看板是鼓励项。

## 构建与验证

1. make all构建CLI和原生应用；发布源码附GoogleTest，可离线make test。
2. make test执行单元、CLI、异常归档与并发、工作流回归；make sanitize运行同一组ASan/UBSan测试，不增加独立用例数。
3. make lint检查C++代码；make fuzz运行60秒Huffman随机输入测试，具体次数由当次JSON记录。
4. python3 tests/benchmark.py build/squirrel生成本地性能记录；tests/compatibility.py和tests/soak.py分别验证兼容性与持续运行，参数见--help。长测必须使用新测试目录，不能提前填通过。
5. 应用--self-test执行离屏内部动作；make gui-demo video-inspector构建演示与视频检查工具。真正的系统选择器和鼠标操作仍需按08清单验收。
6. python3 scripts/write_test_report.py和python3 scripts/write_report.py刷新报告；Word由scripts/build_template_report.py生成。统一渲染检查后再打包。
7. 从ZIP独立解压、重建与测试，检查版本、部署目标、签名、SHA256和视频。结果保留在发布校验记录中。

## 文档依赖

应用本身只依赖系统SDK。可选文档依赖由scripts/requirements-tools.txt列出；PPT构建另需托管@oai/artifact-tool，SVG转PNG需sharp。后台PDF转换用LibreOffice，中文字体必须可用。scripts/render_presentation.sh会在macOS上生成独立字体配置并后台转换，不打开桌面窗口；可通过SOFFICE环境变量指定可执行文件。PPT已逐页渲染检查，实际放映统一在李想的Mac验收。

## 版本管理

每次修改后先检查git diff，再构建和测试。以当前提交为起点做后续分支、评审和合并；不要把计划中的三人职责伪装成已经发生的提交。包内source-history.bundle可用git clone恢复历史。在线仓库首次上传已通过匿名克隆核验，记录见test-results/repository-publication.json；后续推送仍需核对远程提交。

个人证书、账号密码、真实工作备份和依赖虚拟环境不进入公开仓库。仓库已按成员要求公开，课程在线分组已由成员确认填写。

## 提交前

实验环境与在线分组信息已记录；项目AI使用截图和另外两名成员的证书按08及10说明补齐。UML、PPT、报告和视频均以0.2.0为准。第9讲要求PPT3分钟、现场操作7分钟、视频不超过2分钟；2026年11月18日23:59前提交小组材料，证书各自单交。若老师另发通知，再按通知调整。

正式封版时运行 `python3 scripts/check_report_artifacts.py . --require-current-inputs`。除核对已审阅的Word和PDF哈希外，它还检查生成时的正文、插图、模板、构建脚本和实验环境字段；正文或图片更新后，旧报告会被拒绝。Markdown阅读稿同样须与当前章节一致。该检查用于材料一致性，不代替逐页视觉复核。

`make package`要求专用项目仓库没有未提交变更，并从当前提交导出完整源码、依赖和文档，避免夹带未跟踪的临时文件。独立校验使用`python3 scripts/verify_release.py 发布ZIP 新校验目录 --with-gui-self-test`：核对全包哈希、签名、报告来源及源码与Git历史逐文件一致性，离线重建运行97项用例，再用包内CLI重放45项黑盒用例。重放不增加独立测试总数；GUI检查仍为内部53项断言。
