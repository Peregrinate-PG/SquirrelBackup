## 松鼠备份需求分析说明书

版本 0.1.0。本文依据《软件开发综合实验》的实验要求、讲义和报告模板，定义 macOS 本地备份软件初版范围，作为设计、编码、测试和验收的共同基线。优先级以数据正确性、原文件保护、操作易用性和扩展功能完整性为序。

### 1 任务概述

#### 1.1 引言

学生需要把一个目录树保存到独立备份文件，并在另一个位置恢复，解决实验资料、课程代码和个人文件的离线副本管理问题。项目以面向对象的软件工程方法推进，交付源码、可执行应用、构建脚本、需求分析、系统设计和软件测试文档。模板中的 UML 图由学生依据单独指导在 StarUML 中手工完成。

#### 1.2 综合描述

产品是新建的独立单机应用，名称为松鼠备份。系统不依赖远端服务器或账号，包含 Cocoa GUI 与 CLI 两个入口，两者调用相同 C++ 核心。核心功能是扫描文件树、筛选、打包、可选压缩和加密、校验及恢复。自动任务在同一进程中运行，包含定时快照、轮询变化检测和任务内保留策略。

普通用户主要使用 GUI 选择路径和密码；熟悉终端的用户通过 CLI 设置完整筛选条件和自动任务；开发和验收人员使用测试脚本检查正确性。无需登录产品账号，访问范围由当前 macOS 用户的文件权限决定。

#### 1.3 运行环境

开发和实测平台为 macOS 15.7.9、arm64、Apple Clang 17、Command Line Tools。编译产物最低系统版本为 macOS 15.0，实测版本为 15.7.9，其他版本不作为已验证兼容性。使用本机磁盘，目标父目录必须存在。建议测试时预留原始数据数倍的可用空间，因为打包、加密和恢复暂存会产生中间文件。

标准构建需要 clang++、SDK 和 make；GoogleTest 仅用于测试。普通使用不需要 Python。文档生成和黑盒测试使用 Python 开发工具，不参与备份后端。软件不需要网络；首次获取开发依赖可能需要网络。

### 2 功能需求

#### 2.1 功能划分与唯一编号

| 编号 | 功能及约束 | 验收标准 |
| --- | --- | --- |
| FR-01 | 目录树备份 | 普通文件二进制内容、层级和空目录可备份；输出在源树之外 |
| FR-02 | 安全恢复 | 只恢复到新目录；哈希一致；失败不覆盖已有路径 |
| FR-03 | 特殊文件 | 保留软链接目标字符串、硬链接关系和 FIFO 类型；不读取 FIFO 内容 |
| FR-04 | 基础元数据 | 记录权限、UID/GID、atime/mtime 纳秒时间、xattrs；无法恢复属主和属性时警告 |
| FR-05 | 路径筛选 | 相对路径通配符匹配；目录结构保留 |
| FR-06 | 类型筛选 | f/l/p 选择文件、软链接和管道；硬链接按普通文件筛选 |

| FR-08 | 时间筛选 | 按 mtime 秒级上下界筛选，含边界 |

| FR-12 | 自定义打包 | 所有数据及元数据保存在单个 .sqbk 文件，不调用 tar/zip |
| FR-13 | Huffman 压缩 | 每块最大 1 MiB，无损；压缩收益不足则保存原始块 |
| FR-14 | 密码加密 | AES-256-CBC 加密与 HMAC 校验，随机盐和 IV，错误密码失败 |

#### 2.2 系统用例

用例 UC-01 创建备份。参与者为本机用户，触发为点击“开始备份”或输入 backup 命令。前置条件是源为可读目录、输出父目录可写、输出路径不存在且位于源树之外。基本流程：收集路径和选项，校验参数，扫描并筛选，记录元数据，自定义打包并按块压缩，封装加密或摘要，刷写备份文件，以不覆盖方式发布输出。成功后产生完整 .sqbk 文件及摘要统计。源文件变化、磁盘不足、权限错误等均以失败结束，既有输出不受影响。

用例 UC-02 恢复备份。参与者为本机用户。前置条件是备份可读，目标父目录可写，目标路径尚不存在。基本流程：验证格式和摘要／认证标签，解密至私有目录，校验记录并恢复数据及特殊文件，恢复元数据，检查结束标志，独占重命名发布目录。错误密码、损坏、越界或非法路径中止操作，不发布目标目录。不能写入新目录时保留原备份。

用例 UC-03 验证或查看。用户选择备份与可选密码。系统验证全部数据及记录；验证成功后显示统计，查看模式额外返回条目。该操作不修改用户源数据和恢复目录，但会创建并清理私有临时文件。任何校验失败返回明确错误。

用例 UC-04 定时任务。用户指定源、已有存储目录、周期和保留份数。系统为本次运行分配独立任务目录，立即备份，等待周期，生成后续快照，成功后淘汰超出数量的旧快照。失败时记录错误并延迟重试，不淘汰上次成功快照。停止请求使任务在当前快照完成后退出。

用例 UC-05 实时任务。用户开启实时模式。系统立即备份，然后轮询被筛选目录的元数据；发现变化后，等待下一次观察确认稳定，再执行备份。若持续变化则继续等待；任务失败会重试。该用例不承诺内核事件级延迟或事务级文件系统一致性。

用例 UC-06 筛选备份。用户设置任意组合的路径、类型、名字、时间、尺寸和 UID 条件，以及排除规则。系统先判断排除，再对非目录条目应用 AND 条件，目录保留以满足树结构；选定硬链接的首次出现保存数据，之后只保存关系。非法时间或尺寸范围在备份前拒绝。

用例图位置及元素安排见《StarUML 绘图指导》第 2 节，由学生绘制后插入模板 2.2 系统用例位置。

### 3 外部接口需求

#### 3.1 用户界面

GUI 采用 macOS 文件选择器、路径输入框、压缩和加密选项、密码框、动作按钮、状态指示和滚动日志。创建、恢复与自动任务分页面显示。密码不回显到日志。执行期间禁用新的业务动作，避免并行写同一任务；错误以日志和状态栏提示。CLI 成功返回 0，失败返回 1，进度写 stderr，结果写 stdout。文件名含换行时 CLI list 使用引号和转义显示。

#### 3.2 硬件接口

通过操作系统文件系统接口读写本地存储，无自定义硬件协议。软件不直接访问块设备，不要求管理员权限。外置卷的元数据能力和授权不属于当前实测范围。

#### 3.3 软件接口

核心公开头文件为 include/squirrel/backup.h。BackupService 提供 backup、inspect、restore；Scheduler 提供 run。运行时依赖 C++ 标准库、POSIX、Cocoa 和 CommonCrypto/Security。自定义文件格式版本固定为 1，未知版本拒绝；不承诺与 tar、Time Machine 等其他格式互通。

### 4 其它非功能性需求

正确性 NFR-01：测试数据恢复后的 SHA256 应与源一致；空目录和特殊文件结构正确。安全性 NFR-02：拒绝绝对路径、父路径跳转、重复路径、非目录父节点和非法硬链接，且备份和恢复不覆盖已有目标。可维护性 NFR-03：算法、文件扫描、格式、封装、调度和 UI 分离，避免复制两套业务逻辑。

资源 NFR-04：普通文件按 1 MiB 块处理，内存还包含全量条目与元数据列表，不宣称总体常量内存。格式设定单文件 1 TiB、条目数 100 万、文本字段 64 KiB、每条目 xattrs 总计 64 MiB 的上限；这些是防御性边界，不是已完成的容量测试指标。性能 NFR-05：提供本机实测时间、输入输出大小和哈希比对结果，不把缓存条件下的测量作为吞吐承诺。

健壮性 NFR-06：采用私有暂存目录和不覆盖发布，磁盘不足、截断、密码错误应给出错误。源文件变化检测基于大小、inode、mtime 的前后对比，不能等同于 APFS 一致性快照。系统断电或强制 kill 后可能遗留临时目录，不保证安全擦除或电源故障后的持久性。

## 松鼠备份系统设计文档

版本 0.1.0。本设计对应需求 FR-01 至 FR-21，说明已实现的 C++ 类、文件协议、恢复安全边界和调度逻辑。文档中的方法名以 include/squirrel/backup.h 为准；UML 图由用户根据指导手工绘制，不在本交付物中生成。

### 1 开发环境和工具

#### 1.1 开发环境

开发平台为本机 macOS 15.7.9 arm64，Apple Clang 17 与系统 SDK，C++17、Objective-C++、GNU make 3.81、git 2.39.5 和 VS Code。通过 -Wall -Wextra -Wpedantic -Werror 编译业务源码；CommonCrypto 的系统废弃声明告警单独屏蔽，不视为算法自研。GoogleTest 执行白盒测试；Python 驱动 CLI 黑盒和性能测试；AddressSanitizer 与 UndefinedBehaviorSanitizer 用于动态检查，适配本机平台而不强行安装 Linux 的 perf 或 valgrind。

#### 1.2 依赖库

GUI 使用 Cocoa/AppKit，密码封装使用 CommonCrypto/Security。打包、Huffman、筛选和调度由本项目编写。GoogleTest 只链接测试程序。详细来源、许可和扩展功能计分说明见 THIRD_PARTY.md。

### 2 总体设计

#### 2.1 系统结构设计

入口层由 cli.cpp 和 gui.mm 构成。CLI 解析参数、读取密码环境变量并处理退出码；GUI 收集输入，在后台队列调用业务服务，在主队列更新日志。业务层由 BackupService 统一编排，Scheduler 提供循环快照。基础模块分为 FileScanner、ArchiveWriter、ArchiveReader、HuffmanCodec 和 CryptoEnvelope。

构建时核心源文件生成 libsquirrel.a，GUI 和 CLI 静态链接同一核心。当前不提供对外稳定 C ABI 或动态库；若后续需要脚本 UI 或插件，才考虑增加不传播 C++ 异常的 C 接口。组件图需要展示两个入口对同一核心库的依赖及核心库对文件系统、密码库的依赖，具体绘图步骤见指导第 4 节。

备份子系统接收源目录和 BackupOptions，输出单个封装文件与 Summary。恢复子系统接收备份和新目标路径，验证后输出新树和统计。自动任务复用 BackupService，不单独复制打包逻辑。

### 3 静态建模

#### 3.1 系统对象模型

核心类关系以静态工具方法依赖为主：BackupService 依赖 FileScanner、ArchiveWriter、ArchiveReader、CryptoEnvelope；ArchiveWriter 和 ArchiveReader 依赖 HuffmanCodec；Scheduler 依赖 BackupService、BackupOptions 与 ScheduleOptions。它们不通过继承形成多态层次，不应在类图中臆造父类。

值对象组合关系：BackupOptions 拥有 1 个 Filter、压缩开关和密码；Entry 拥有路径、链接、类型、权限、属主、时间、尺寸和 0..* 个 xattr 键值；Summary 拥有统计和 0..* 个 Entry（仅收集模式返回列表）。Filter 拥有 0..* 条排除规则。服务类本身不长期保存 UI 状态。GUI 控制器负责窗口及任务停止标志，异步操作期间保持控制器存活。

#### 3.3 扫描与文件类型

扫描对目录子项排序，保证相同目录状态下顺序稳定。lstat 避免把符号链接当目标文件展开，readlink 记录链接字符串。普通文件通过 device/inode 对识别硬链接：被选中的第一次出现保存数据，后续记录引用该路径。FIFO 只记录类型和元数据，不打开读取。遇到 socket 或设备节点直接报错。

路径与名字通配符通过 fnmatch 实现，不是正则表达式。规则不跟随符号链接。全量 Entry 列表在内存保存，因此内存复杂度为 O(条目及扩展属性总量)，文件内容处理额外为 O(1 MiB)。

### 4 动态建模

#### 4.1 场景一 创建备份

顺序为：入口收集参数，BackupService 校验根目录和输出位置，FileScanner 生成条目，ArchiveWriter 编写树记录并调用 HuffmanCodec，CryptoEnvelope 封装完整性或加密，fsync 备份文件，link 独占发布输出，返回 Summary。压缩发生在加密之前。

普通文件由 openSource 逐级 openat 并启用 O_NOFOLLOW 打开，避免父路径被替换为符号链接后跟随读取。打开前后比对 size、device/inode、mtime；变化则失败，不把变化中的文件作为成功备份。该策略不能保证多文件事务一致，也无法检测攻击者精确恢复元数据的内容变化。

#### 4.2 场景二 验证与恢复

CryptoEnvelope 用一个 O_NOFOLLOW 文件描述符读取备份，先验证完整 payload 的摘要或 HMAC，再解密／复制至私有临时文件。第二遍读取再次计算摘要，检测两遍之间的内容变化。ArchiveReader 随后校验树并恢复至私有暂存目录。目录临时权限为 0700，普通文件以 O_EXCL/O_NOFOLLOW 和 0600 创建；链接父节点必须是已知目录，硬链接只能指向先前普通文件。

每个非目录条目创建后应用元数据，目录在全部内容处理后按逆序应用权限和时间，避免创建子项破坏最终时间。读取完整结束标志并确认无尾随数据后，用 macOS renamex_np(RENAME_EXCL) 将暂存目录发布到新目标。失败不覆盖既有文件。

#### 4.3 场景三 自动任务

Scheduler 创建本次专属 squirrel-job- 随机目录，生成 snapshot-1.sqbk 等完整快照。成功快照登记到 owned 队列，超过 keep 才删除最旧文件。失败日志不触发淘汰。定时模式以单调时钟判断距上次完成的间隔；不补跑睡眠期间错过的周期。

实时模式每 poll_seconds 扫描一次，根据路径、类型、大小、inode、mtime、权限、UID/GID、链接目标和 xattrs 构造状态字符串，不包含 atime，避免备份读取触发自身循环。状态与基线不同且与上次候选相同才备份，即等待两个连续稳定观察。使用轮询并非 FSEvents 内核通知，实现简单但大目录扫描开销较高。

#### 4.4 状态与线程

界面状态为就绪、执行中、完成、失败；自动任务增加等待与停止请求。执行中禁止新的业务操作，停止标志仅用于自动任务循环，不会中断正在写入的备份。因此停止响应时间包含当前快照耗时。窗口关闭或退出时若忙碌，提出停止并要求等待操作结束，避免主动截断写入。

状态图和两个顺序图的逐条消息清单见 StarUML 指导；尚未绘制的图不作为已完成建模成果申报。

### 5 数据持久化与文件格式

#### 5.1 持久化选择

初版无数据库。备份自身存储元数据；任务运行时状态在内存，任务生成的备份留在独立目录。GUI 参数和密码不写配置文件，应用重启后需重新设置。跨进程恢复历史调度计划尚未实现。

#### 5.2 外层 SQBK 版本 1

所有多字节整数均小端，文本和二进制长度显式指定，禁止直接写入 C++ struct 的平台内存布局。外层头固定 44 字节：8 字节 ASCII SQBK0001，1 字节加密标志（0/1），3 字节保留零，16 字节 salt，16 字节 IV；其后为 payload，最后 32 字节为 tag。未加密时 salt/IV 为零，tag 是 header+payload 的 SHA256。加密时 tag 是 header+ciphertext 的 HMAC-SHA256。

PBKDF2-HMAC-SHA256 固定 200000 轮，派生 64 字节，前 32 字节为 AES-256 密钥，后 32 字节为 HMAC 密钥。salt 和 IV 分别由安全随机数生成，AES 使用 CBC 与 PKCS7 补齐。认证标签逐字节异或累计后判断，先验证后解密，不把密码摘要直接保存成可用于解密的密钥。密码最低 8 UTF-8 字节，并不代表强度保证；不存在找回机制。

#### 5.3 内层 SQTREE 版本 1

开头为 8 字节 SQTREE01 和 8 字节条目数。每个条目依次为 type(u8)、path(长度 u32+字节)、mode/uid/gid(各 u32)、mtime 秒(i64)+纳秒(u32)、atime 秒(i64)+纳秒(u32)、size(u64)、link(长度文本)、xattr 数量(u32)，随后是各属性的名称和二进制值（均带长度）。根目录是第一条，path 为空。

Regular 条目后跟内容块，直到原始 size 被满足。每块包含编码标志(u8)、原始长度(u32)、存储长度(u32)、数据。编码 0 为原始块，1 为 Huffman。块原始长度 1..1048576；空文件没有内容块。Hardlink 保存首次 Regular 的路径和逻辑 size，没有重复数据。结束为 8 字节 SQEND001，之后不得有数据。

Huffman 块先记录 256 项 u32 频数表，再记录从高位起排列的比特。以优先队列按频数、节点索引确定合并顺序；相同频数可重建同一棵树。单符号块无需位流。编码长度不小于原始块时，写原始块，避免不可压缩数据膨胀。解码检查频数和、频数分布、位流长度及零填充，不允许尾随有效数据。

#### 5.4 输入校验与资源约束

拒绝路径中的 NUL、绝对路径、空分量、点或父目录分量、重复条目、缺失父目录、非目录父节点、未知类型、非法权限和时间纳秒值。读取长度前设置文本、条目数、xattr 和块的上限。相对或绝对软链接目标可原样保留，但不能作为恢复其他记录的父路径；用户恢复后手动跟随链接可能访问源树外位置，应按普通文件系统链接理解。

### 6 风险与迭代

UID/GID 记录和异属主恢复分开处理，无权限只警告。xattrs 设置失败警告；ACL、出生时间、flags 不支持。原始块和加密中间数据会暂存磁盘，使用权限隔离而非安全擦除。强制中止可能留下 .squirrel- 前缀私有目录；不可自动删除不属于本次运行的路径。

备份发布前刷写单文件，但未实现所有恢复文件及父目录的 fsync 链，因此不承诺断电事务持久性。跨卷、跨平台和超大容量仍需实测。优先迭代应包括 GUI 点击验收、任务取消、扫描竞态强化、可恢复的任务配置与更完整元数据支持。

### 3 代码测试

业务源码使用编译器严格告警，已执行 clang-format 与 cpplint。cpplint 使用 100 列规范，明确关闭六个与项目约定不一致的检查：build/c++17（本项目要求 C++17）、build/header_guard（使用项目稳定命名）、build/namespaces（CLI 局部 using）、build/include_order 和 build/include_subdir（本项目包含路径约定）、runtime/references（公开 API 使用 const 引用）。其它检查保留。输出见 lint.log；零剩余告警不能说明不存在逻辑缺陷。

AddressSanitizer 和 UndefinedBehaviorSanitizer 通过 make sanitize 对核心与 CLI 测试运行，结果见 sanitize.log。它们不替代多线程竞态检查、全系统泄漏审计或强制掉电测试。本机没有把 Linux 的 perf、valgrind 安装记录虚构进报告。

### 4 性能测试

方法为临时生成数据，使用单调高精度时钟统计 CLI 完整备份和恢复耗时，再比较恢复 SHA256。单次运行、同机本地卷、可能受文件系统缓存和负载影响，不作多次统计结论。系统 time -l 获取资源指标因 sysctl 权限受限失败，已改为无额外权限的墙钟测量，未取得可靠峰值 RSS，表中不报告该项。

### 5 健壮性与安全测试

已覆盖短密码、缺失密码变量、未知参数、无效数值、错误范围、截断、篡改、重复路径、非法类型、超大长度、路径跳转、畸形 Huffman、尾随数据和并发发布等情况。恶意归档带正确的未加密 SHA256，确保测试进入树解析器而非全部停在外层校验。

## 八 实验结论

初版已形成目录树备份、单文件封装、可选压缩加密、验证查看、安全恢复以及自动快照的整体闭环。C++ 核心与原生 GUI、CLI 分离，源码和构建脚本可以在本机重建。自动测试证据与范围见前述测试报告。

## 九 总结及心得体会

本项目的工程重点是让需求、设计、实现和测试一致。一次成功的备份不仅是复制字节，还涉及软硬链接、时间权限、格式边界、密码错误和恢复路径安全。对已有目录采用不覆盖策略、把完整性检查放在恢复之前、通过同一业务核心支撑两个入口，降低了数据破坏风险和维护成本。

开发中遇到 GUI 自动操作未获准、系统性能计时权限受限、Python 文档包版本不兼容等问题，分别通过核心自动测试、普通高精度时钟和固定兼容依赖继续推进，避免可选问题阻塞整个交付。以上是本轮实际过程，不是虚构小组成员的个人心得；每位成员的沟通、分工和学习体会请按实际情况补充。
