松鼠备份复核结论与后续安排

复核日期 2026年10月29日。输入为课程资料压缩包、SquirrelBackup 0.1.0 发布包及剩余事项截图。此次在独立副本上整理 0.1.1 修订版，保留原始压缩包。

现有项目已具备完整本地备份流程、独立源码、构建脚本、自动测试和较完整的报告草稿。当前没有必要推倒重写，也不建议为了扩大功能清单立即增加网盘或增量备份。最有价值的工作是修复已复现缺陷，然后把人工验收、建模、在线协作和个人材料补齐。

一 原版到底完成了什么

原版使用 C++17 实现扫描筛选、归档、Huffman 编解码和任务调度，使用 Cocoa 提供原生 GUI，使用系统密码库提供加密。恢复有私有暂存目录、不覆盖已有目标和归档校验；源码包含 GoogleTest、CLI 集成和畸形归档测试。原有 33 项单元、21 项集成、18 项异常及并发测试，本轮在改代码前复跑均通过。

72 项通过是既有测试范围内的结果。它不能证明图形文件选择器、现场点击、所有权限组合和长期运行已经验收。现有三个界面图片属于离屏预览。原版 PPT、个人心得和 A/B/C 分工仍是待完善草稿。

二 本轮修订重点

最终测试数量、运行环境和具体用例见 03_软件测试报告。不能把 GUI 断言数、Sanitizer 再次运行次数或稳定性循环次数加进命名用例总数。

仍保留的边界：自动任务只在应用运行时有效；停止会等待当前快照完成，尚未实现大文件中途取消；实时监测仍是轮询，不能保证捕获两次采样之间产生又消失的变化；不支持网络、增量、ACL、设备文件和完整 macOS 元数据；不同属主恢复可能因权限不足产生警告。格式上限不是实测容量。

三 图片中需要调整的判断

  1. 先完成程序修复和回归，再按最终接口绘制 UML，避免画完又改。
  2. 课程要求 UML 建模和掌握 StarUML；材料中的“不要生成 UML”属于历史任务口吻，不是本轮用户指令。本次完善绘图指导，模型和正式图仍待小组制作、核对。
  3. 用例编号已统一，需求、设计和绘图指导应使用同一组编号。不能照原来两套编号分别画图。
  4. 在线 GitHub/Gitee 版本库是第 2 讲的项目要求，Teambition 或类似工具是鼓励使用。不要伪造历史协作记录，应记录接下来真实的分支、提交、评审和合并。
  5. 报告模板和答辩要求均提到甘特图。现有阶段列表不足以代替有日期、负责人、里程碑的甘特图。没有证据的历史日期保留待核实，后续安排可以作为计划。
  6. PDF 报告已经有基础；课程包没有明确要求必须只交 Word。若最终平台要求 DOCX，再按给定模板转换，并检查分页和图表。
  7. “程序、材料已具备”应理解为初稿齐全，不能直接视为正式可提交。

六 交付物如何使用

修订版 ZIP 包含 0.1.1 原生应用、命令行、源码、构建脚本、当前测试记录及修订报告。先读本文件，再读 08_提交前验收清单。

在 source 目录运行 make all 和 make test 可离线构建与验证核心程序；制作人工验收数据可运行 python3 scripts/prepare_acceptance.py 后接一个尚不存在的目录路径。所需父目录须已存在。脚本生成演示数据和内容 SHA256，不接触个人文件。

presentations 目录保留输入包中的 0.1.0 可编辑 PPT 和 PDF，已明确标为原始草稿。本轮没有把未经核验的人员信息、UML、视频或学习证书做成“已完成”。本地签名应用未经 Apple 公证，其他电脑上的启动和文件系统行为需实测。
